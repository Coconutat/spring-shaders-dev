# ADR-0001: 双层架构 (Wrapper + Implementation Layer)

**状态**: 已采纳  
**日期**: 2024 (项目初始)  
**作者**: 中影 / ZYPanDa

## 背景

Minecraft 光影包需要为三个维度（主世界、下界、末地）分别提供独立的 GLSL 入口文件。简单复制粘贴会导致大量代码重复和维护噩梦。

## 决策

采用双层架构：

1. **包装层** (`shaders/world*/*.fsh|.vsh|.csh|.gsh`)：仅声明 `#version`、注入维度宏（`NETHER`/`END`）和阶段宏（`FSH`/`VSH`/`GBF`），然后通过 `#include "/program/xxx.glsl"` 路由到实现层。
2. **实现层** (`shaders/program/*.glsl` + `shaders/lib/*`)：包含所有实际渲染逻辑，不关心维度差异。通过条件宏 `#ifdef NETHER` / `#ifdef END` 处理维度特化逻辑。

## 权衡

| 选项 | 优点 | 缺点 |
|------|------|------|
| **双层架构 (选定)** | 单份实现代码，三份轻量包装；修改维度行为只需改包装宏 | 需要维护维度路由映射表；包装文件和实现文件的对应关系隐式约束 |
| **每维度复制实现** | 各维度独立修改灵活 | 三份重复代码，修改一个功能需改三个文件；极易产生不一致 |
| **运行时维度检测** | 无包装层，宏更少 | GLSL 编译器无法优化掉死分支；被淘汰的维度代码仍会编译 |

## 影响

- 新增 program 需要在三个 `world*/` 目录各创建一个包装文件。
- `world__1`（下界）使用双下划线命名，区别于 `world_1`（末地），容易混淆，但与文件系统路径解析兼容。
- 跨维共享改动通常需要三处对齐（包装文件中的宏定义）。
